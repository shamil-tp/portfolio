OpsPilot

Agentic Incident Response & DevOps Copilot

Project Overview

OpsPilot is an AI-assisted incident response and DevOps copilot with deterministic backend controls and human approval for risky remediation. It investigates a production incident from structured operational evidence — logs, health, deployments, previous incidents, GitHub CI/CD events and AI code reviews — identifies the most likely root cause with citations, proposes a safe fix, waits for a human to approve it, verifies recovery with objective checks, and writes the incident report.

Its guiding rule: the AI proposes, the backend validates, a human approves risky actions, the backend executes only allowlisted actions, and verification decides — not the model. It runs in a repeatable demo mode and against real projects, which are health-checked continuously and get an AI code review on every push to main.

How The Project Works

OpsPilot runs a closed, explainable loop over evidence the backend collects itself. Each step is a REST command that moves the incident through a strict state machine and is safe to repeat — out-of-order steps return 409.

1
Detect — a health check every 60 s records status and latency; 2 consecutive DOWN checks (or 3 failing) open an incident. Signed GitHub webhooks record what changed: pushes, workflow runs and deployments.
2
Investigate — the backend gathers bounded evidence (±10 min of logs, health vs. baseline, dependencies, deployments, past incidents, CI/CD events) through read-only tools, then makes one structured Gemini call.
3
Root cause — the AI returns a causal chain, contributing factors and ruled-out alternatives. Every claim must cite evidence ids (L5, D1, C3…); unknown ids are dropped.
4
Remediate — the Remediation Agent proposes an action; backend policy validates it against an allowlist, sets the risk level, checks rollback targets against real deployment history and creates a PENDING approval.
5
Human approval — an operator approves or rejects. Approve takes no request body: the backend re-validates and executes exactly the stored parameters.
6
Verify — six deterministic backend checks decide RESOLVED or FAILED; the AI only writes the summary.
7
Report — the incident report is assembled from stored results with no AI call, downloadable as Markdown, JSON or PDF. Every step streams to the dashboard over WebSocket.

Key Features

  • AI Investigation: One structured Gemini call over bounded, deterministic evidence gathered by read-only tools.
  • Cited Root Cause Analysis: Causal chain, contributing factors and ruled-out alternatives, each tied to evidence ids.
  • Human-Approved Remediation: AI proposes, backend policy validates and sets risk, a human approves before anything executes.
  • Deterministic Verification: Six backend recovery checks decide whether the incident is resolved.
  • GitHub CI/CD Evidence: Signed webhooks become deployment telemetry, so "what changed?" is answered with real commits and workflow runs.
  • AI Code Review on Push: Every push to main on a monitored project is reviewed — severity, file:line, explanation and fix — with secrets redacted first.
  • Continuous Health Monitoring: Live projects are checked every 60 s and incidents open automatically.
  • Real-Time Dashboard: WebSocket event stream with automatic REST polling fallback.
  • Reports: Incident, code review and project reports as Markdown, JSON or PDF.
  • Repeatable Demo Mode: One-click simulated payment-api incident with full reset.
